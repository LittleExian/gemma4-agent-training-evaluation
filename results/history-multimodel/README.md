# Historical multi-model evaluation evidence

Eight independent completed full129 configurations are indexed in `index.json`: seven arms in the repaired comparison experiment and one separate Teich top-k=64 rerun. Each includes 129 unique task IDs: 126 eligible and three preflight exclusions. The original comparison experiment completed six pilot16 arms, then stopped at an owned-process cleanup safety check. Those pilots were imported into the repaired experiment; they are not additional full129 runs. Full129 tasks were generated afresh rather than reusing pilot patches.

Each full129 directory contains per-task JSON/CSV, summary, actual request sampling and server launch configurations, raw-source hashes, and candidate agent patches. `resolved` means the existing evaluator accepted the generated patch; timeout and unresolved counts are retained separately. Excluded tasks keep their recorded false resolved values but do not contribute to the eligible denominator. Missing fields remain missing/null.

All full129 configurations used 15 minutes per task, 56 tool calls, 160 turns, 6,000 thinking tokens, 8,192 output tokens, 32,768 context, temperature 0.2 and top-p 0.95. Three GPUs (0/2/3), four slots per GPU, and tensor parallel size 1 were recorded. The system-prompt budget text agrees with the runtime evaluation configuration. Per-arm configuration files preserve model, quantization, adapter, parser and top-k distinctions. In particular, model generation defaults are not assumed active for servers started with `--generation-config vllm`. The separate Teich rerun sets top-k=64 through the server override.

Full task packages, reference/gold/test patches, raw traces, complete prompts/messages, and raw test outputs are not published. Their original hashes are retained when available. Candidate patches are accepted for export only from an `agent-*` invocation with a matching task ID and no externally supplied patch_file. They are generated candidates, not reference answers.

Server paths are displayed under `/workspace`, and the server address is replaced by `SERVER_HOST`. Original hashes describe the unmodified source bytes; published hashes describe sanitized copies. Small historical code/config snapshots and a deduplicated manifest are under `history-sources/multimodel/`. The snapshots document history; they are not a claim that the old runs can be launched unchanged on a different server.
